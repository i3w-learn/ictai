Offline-First ICT Lab Classroom Platform

A classroom system for one school computer lab. One server PC runs everything. Up to 60 student PCs connect to it over the lab's local network. The school never needs the internet to teach.

Author: Rishabh Dhiman, Product Manager Audience: development team only Companion to product PRD v0.4
P0 first pilot P1 general release P2 later
Part 1 · The big picture

In one minute

  • Windows only. Windows 10 (22H2) and 11, 64-bit. No Android, iOS or web apps.
  • One lab, one server. One server PC (wired), optionally plugged into a smart board or projector by HDMI, plus up to 60 lab PCs.
  • Works with no internet. The internet is only used for cloud check-in, downloads and uploading usage numbers.
  • Student data stays on the server PC. Only app usage numbers go to the cloud, never names, marks or answers.
  • AI runs on the server PC too. Lesson plans, quizzes and a student tutor work without the internet.
  • Tools are not chosen yet. The PRD says what to build. Languages, frameworks and databases are left to the tech team.

The three apps

One Windows installer. Its first screen asks "Server or Student?". The console and the Student app share one UI codebase, built two ways.

Server app

the lab's main PC · Super Admin, Teachers

A Windows service that starts at boot and holds all data and logic. Next to it: a local AI runtime, the console window teachers use, and an optional full-screen Present window for the HDMI display.

Student app

each lab PC · Students

A desktop app with a local cache for books and an offline outbox: answers and work wait there until the server confirms it got them.

Cloud platform

our hosting · tech team only

School registry with an admin UI, licence service, check-in API, content and update store, USB kit builder, and the analytics warehouse.

Design rules

These choices shape everything else in the document.

A

Offline first

Every school feature works with no internet. The cloud is only for check-in, downloads and analytics.

B

The server owns everything

All data and logic live in the server service. The console and Student app are thin screens that talk to it over REST and WebSocket.

C

The cloud never calls in

The cloud can't reach into a school. The school server starts every cloud request, over HTTPS.

D

Never lose an answer

Answers, attendance and submissions must be confirmed ("acked") by the server. Until then the Student app keeps them in its outbox and resends.

E

Everything from outside is signed

Licences, updates, content, AI models and USB kits are signed and checksum-verified before use, so the school can trust them even offline.

F

Privacy by allow-list

Analytics accepts only a fixed list of fields. Anything else is rejected, and an automated test checks this.

G

AI stays local

Open models run on the server PC, on localhost only. If no model is installed, AI features show an empty state instead of failing.

What leaves the school

Stays on the server PC

  • Students, teachers, passwords and PINs (hashed)
  • Quiz results, marks, attendance, answers
  • Submissions, report cards, student analytics
  • Recorded lessons
  • AI prompts and outputs (deleted after 90 days)

Sent to the cloud

  • School ID, app and model versions
  • Health: uptime, free disk, PCs online, upload backlog
  • Usage events with counts only, e.g. "lesson presented, 38 minutes, 32 PCs joined"
  • Role names like "teacher", never a user ID

Part 2 · Features

Teacher console

Runs on the server PC's monitor. Everything is open to Super Admin and Teachers unless marked.

People and lab setup

Overview P0

Today's lessons, PCs connected, students signed in. Alerts for offline PCs, low disk, licence expiring, or no check-in for 14+ days.

Students P0

Add, edit, import from Excel/CSV, move section, promote class, print PIN/QR cards. Soft delete and duplicate check (name + class + roll).

Staff P0

Super Admin only

Add, edit, delete teachers; reset passwords. Deleting ends their sessions; their content stays.

Devices P0

Enrol lab PCs in a 30-minute window. Rename, retire, lock, unlock, restart app, "look at the front". PC limit comes from the licence.

Master data P0

Classes, subjects and languages come from the school profile (read-only). The school names sections and sets period times.

Content P0

PDFs, images, video, audio, slides, HTML5 packages, video links, filed by class, subject and chapter. Max 512 MB per upload. Files are de-duplicated by their SHA-256 fingerprint and indexed for AI.

Timetable P1

Weekly lab grid by period with clash checks. Drives the week ahead, the student Today screen and reminders.

Teaching and assessment

Quizzes & polls P0

Single, multiple, true/false, image, number, short text. Polls: choice, rating, word cloud. Live run with server-timed countdown, tally, reveal, leaderboard. Team mode is P1. Can be generated with AI.

Plan a lesson (AI) P0

Give a topic, class, subject and minutes (default 40). Get objectives, timed steps, library items, checks and homework. Edit, then save or present.

Work P0

Assignments from a quiz, worksheet, file task or library item, with due date and marks. Students submit text, file, drawing or webcam photo. Late work is flagged.

Activities P0

Offline interactive packages from Anganwadi to Class 12. They run sandboxed and report score, time and completion.

Playlists P1

Ordered videos, links, PDFs and activities for a chapter. Items that need internet are skipped when offline.

Learning paths P1

Steps: watch, read, activity, quiz check, assignment. Optional prerequisites. AI can draft one from the library.

The week ahead P1

Mon–Sun plan per slot. 5 minutes before, a reminder fires and the files are pre-loaded onto that class's PCs.

Recorded lessons P1

Records the Present screen and audio (no camera). Stored on the server; replay from My books.

Notices P1

One-way notices to the school, a class or a section, with pin and expiry.

Study rooms & Together monitor P1

Teacher-run group space with whiteboard. Teachers can see, join, watch or close student Together rooms.

Results and system

Quiz results & marks P0

Per student and class, export to Excel/PDF. Never included in the analytics upload.

Student analytics & reports P1

Attendance, accuracy by chapter, work on time, weakest chapters. Computed locally.

Report cards P1

Built from marks with teacher remarks. Draft, then published, then frozen (can't be changed). PDF print.

Licence P0

Signed token checked offline. 30-day grace period. Super Admin renews online or with a file.

Updates P0

Install, roll back, import an update kit, set a policy. Never installs during a live lesson.

Settings & Server manager P0

Super Admin only

School details, sign-in method, AI switches, backup location. Relay and AI status, PCs that "could not reach", check-in backlog, export analytics to USB.

Present mode

Optional. Used only when a smart board, projector or TV is plugged into the server PC. Without one, the teacher runs the lesson from the console and reads the join code aloud.

  • Two screens: Present is full-screen on the board; the console stays on the server monitor. One screen: Present is full-screen with a floating control bar.
  • Shows: idle screen (school, period, clock, next lesson), content, join code, quiz countdown and results, whiteboard, playlist steps, Ask AI (P1).
  • Controls: next/previous, play/pause, annotate, whiteboard, quiz start and reveal, blank, lock lab PCs, show/hide code, end lesson. Keyboard shortcuts and USB touch.
  • Safe by design: the Present window can never show student lists, results or settings.

Student app

Sign-in P0

Pick class, tap your name or photo, enter PIN. Or show your QR card to the webcam.

Today P0

Greeting, current lab period, and "Join the lesson" with a 6-digit code. Clear messages for wrong or expired codes.

In-lesson view P0

Follows the teacher's screen. Answer quizzes, draw when given the pen, private notes, raise hand, "I'm stuck". Can be locked or blanked.

My books P0

Books and library items by subject and chapter, plus recorded lessons. Cached on the PC (up to 10 GB). Remembers your page.

Things to do & My work P0

Activities, playlists, path steps and assignments. Submit text, file, drawing or photo, even offline.

Settings & status P0

Language, text size, high contrast, dyslexia-friendly font (WCAG 2.1 AA). A status chip shows "Connected" or "Working offline: N answers waiting".

How I am doing P1

Your own attendance, accuracy by subject, path progress and "try this next". Only your own data.

Together P1

Shared whiteboard for up to 6 students, joined by code. No chat or voice. A banner says the teacher can see the room.

Ask (AI tutor) P1

Answers from the school's own books, with citations. Gives hints, not assignment answers. Daily limit.

Part 3 · How it works

The server service

Startup order

  1. Starts at boot and restarts itself if it crashes.
  2. Takes a single-instance lock, opens the database, runs migrations, checks the licence.
  3. Listens on TCP 7700 (private networks only) and UDP 7701. If 7700 is taken, the console shows which program has it.
  4. Starts the AI runtime if models are installed, at lower priority.
  5. Starts background jobs. The console connects to localhost:7700.

Background jobs

JobWhenWhat it does
Check-inEvery 15 min, if onlineHeartbeat to the cloud, then act on what comes back
DownloadsAfter check-inContent, updates, models. Resumable; checksum and signature verified
AnalyticsNightly roll-up, upload after check-inSeal batches, upload oldest first, go slow during school hours
BackupNightlyDatabase + file list to the backup folder; keep 7
IndexingWhen content changesExtract text, split into chunks, embed for AI search
RemindersEvery minuteLessons starting in 5 min: notify console, pre-load files
CleanupNightlyExpire codes, close idle rooms, delete AI prompts over 90 days, drop unsent analytics over 180 days

Windows setup

  • The installer opens TCP 7700 and UDP 7701 in the firewall for Private networks, and warns on Public ones.
  • The school key and licence are encrypted with Windows' machine-level protection.
  • The licence is tied to the main physical network card. Virtual adapters are ignored.

Finding the server

No one types an IP address. A lab PC shouts on the network and the server answers with every address it has.

sequenceDiagram
  autonumber
  participant P as Lab PC (Student app)
  participant B as Beacon (UDP 7701)
  participant S as Server API (TCP 7700)
  P->>B: broadcast {"t":"discover", app, ver}
  B-->>P: {"t":"here", schoolId, name, addrs[], port}
  loop each address
    P->>S: GET /health (2 s timeout)
    S-->>P: schoolId
  end
  Note over P: keeps the first address with the same schoolId
  alt no answer after retrying every 3 s for 10 s
    Note over P: manual IP, a connection file from USB, or mDNS
  end
The server also lists PCs that ask but never connect. That usually means the network is blocking PC-to-PC traffic.

Answers count if the student's timestamp is before the quiz closed, so a slow network doesn't cost marks.

Relay messages

One WebSocket per client at ws://<server>:7700/relay. Every message has the same envelope:

{"t":"<type>","room":"<roomId>","seq":1042,"ts":1729650000123,"id":"<uuid>","p":{...}}
 seq = server order per room   ts = server clock   id = client message id (to drop duplicates)

Rules

  • Role and room are checked on every message. Messages over 64 KB are rejected; big data goes over REST.
  • Slow PCs get a fresh snapshot instead of a growing queue.
  • If the connection drops, the app reconnects after 1, 2, 4… up to 30 seconds, then rejoins and gets the current state.
  • Join codes are 6 digits, unique among open rooms, and die with the room. Wrong guesses are rate-limited.

Cloud and licence

School registry

School ID, UDISE+, district, state, profile, PC quota, field person. Internal admin UI behind company sign-in.

Licence service

Signed licence tokens, plus files for offline activation and renewal.

Check-in API

Receives heartbeats and replies with jobs for the school.

Content & update store

Content packs, signed app builds, AI models, signed manifests. Delivered over a CDN.

Kit builder

Builds a school's USB kit from the registry.

Analytics warehouse

Checks and stores usage events. The tech team's BI tool reads it.

How the school proves who it is

  • At activation the server gets its School ID and licence, makes its own key pair, and registers the public key with the cloud.
  • Every request carries School ID, time and a signature. The cloud rejects unknown keys and clocks more than 10 minutes off.
  • HTTPS with certificate pinning: the server only trusts our own certificate authority.

USB kit

For schools with no internet at all. One folder carries the install, activation, content and updates in, and analytics out.

KIT-SCH-0007-2026-10-23/
  kit.json           signed manifest of everything below
  installer/         signed installer
  activation.lic     signed activation (schoolId, licence, cloud public key)
  profile.json       signed profile (master data, settings, update policy)
  field-people.json  signed field-person list
  content/ models/   packs + manifests
  returns/           server writes analytics exports here

Import checks every signature and checksum, then applies them in order: activation, profile, field people, content, models, app update.

Analytics

Hard rule: analytics events never contain a person or learning data. Only allow-listed fields get through; an automated test checks this.
{"e":"lesson.presented","ts":"2026-10-23T09:05:11Z","schoolId":"SCH-0007","app":"server",
 "ver":"1.0.3","role":"teacher","dims":{"class":"7","subject":"science"},
 "m":{"minutes":38,"pcsJoined":32}}
FieldAllowed
eAn event from the catalogue: lesson.presented, quiz.run, poll.run, work.set, content.opened, ai.request, pc.online, app.crash…
ts, schoolId, app, verUTC time, school, app, version
roleteacher, student, super_admin or system. Never a user ID.
dimsclass, subject, contentId, feature, windowsVersion, errorCode
mNumbers only: counts, minutes, latency, sizes
  • Never allowed: names, usernames, user or student IDs, scores, marks, attendance, answers, free text, prompts.
  • Unsent raw events are kept up to 180 days. Daily totals are never deleted before upload.
  • Uploads are signed ~1 MB batches. Sending the same batch twice is safe.
  • With no internet, the Super Admin exports batches to the USB kit's returns/ folder.
