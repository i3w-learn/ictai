ICT App System Design

One Windows PC in each school runs everything. Lab PCs and smart boards talk to it over the school's own network, so teaching never needs the internet. Our cloud is a back office that the school server calls when it can.

Inside the school Server PC Classroom devices Our cloud (later) USB kit

1 · The big picture

What runs where

Every app is a screen only. All the data and logic live in the server service on the server PC. The cloud never connects into the school; the school server always starts the call.

2 · The apps

One codebase, two installers

All screens come from one Tauri + React codebase. The role is picked at install time.

Windows installer · ICT-Setup.exe

The first screen asks what this PC is:

  • Server: server service, Console app, Present window, local AI.
  • Student PC: Student app in a locked-down window. Sign in, join lesson, quizzes, books, my work, AI tutor.
  • Board: a Windows PC used as the classroom board.

Android board app · ict-board.apk

For Android smart panels at the front of the class. The teacher uses it to:

  • open lessons (PDF, Office, video, slides)
  • draw and write on the whiteboard over any content
  • run live quizzes and show the tally
  • show a student's screen, lock student PCs

3 · How we build it

From a MacBook to a Windows .exe and an Android .apk

We write and run everything on the Mac. A Windows build machine on GitHub Actions makes the .exe. The Android app builds on the Mac with Android Studio's tools.

4 · Finding the server

No typed IP addresses

School routers change IP addresses often. So each device saves the server's ID, not its IP, and asks the network where that server is.

5 · A live lesson

How 40 screens follow the teacher

The board sends each action to the server relay, and the relay copies it to every student PC in the room. Answers are kept on the student PC until the server confirms them, so a dropped network loses nothing.

6 · Licence

A dead internet line never locks a school

The licence is a small file signed by us. It names the school, the server PC's network card, how many PCs and boards are allowed, and an end date. The server checks it offline.

Notes for developers
  • The spec ict-app-final-spec.md is the source of truth. Where Sections 1, 12 and 12.1 still say Flutter, read Tauri 2 + React (Section 17.4 is final).
  • For the first offline Windows version we can skip the cloud. Licences, content and updates arrive on the USB kit.
  • Check Gemma's licence terms for the exact version we ship. The spec requires models allowed for government and commercial use.
